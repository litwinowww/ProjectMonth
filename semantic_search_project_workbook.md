## 1. Заметки со встреч и контекст задачи

Компания CalmFruits развивает онлайн-каталог товаров. Сейчас поиск работает по ключевым словам и плохо справляется, когда запрос не совпадает дословно с карточкой: пользователь пишет синонимы, разговорные формулировки или ищет товар по назначению ("удобные кроссовки для бега" против "мужские спортивные кроссовки с амортизацией").

Задача - построить MVP семантического поиска: перевести запросы и товары в векторы, искать ближайшие товары и оценить качество по готовой разметке. По итогам нужно ответить бизнесу, стоит ли внедрять векторный поиск, где он помогает и где ошибается.

Дано: каталог товаров (200 000 строк), пул оценённых карточек и историческая разметка релевантности (train и test). Разметка синтетическая, запросы стилизованы под пользовательские.

## 2. План базового пайплайна

**2.1. Формулировка задачи своими словами**

По текстовому запросу пользователя система должна вернуть топ-10 карточек товаров, подходящих под запрос. Ищем по каталогу одежды и обуви, где каждая карточка описана единым текстом из категории, названия, бренда, цвета и описания. Качество оцениваем на исторической разметке: для каждого запроса известно, какие товары асессоры сочли подходящими. Бизнесу это нужно, чтобы понять, стоит ли заменять текущий поиск по ключевым словам на векторный.

**2.2. Подготовка данных**

1. Оставили категории "Одежда" и "Обувь" - только они есть в разметке: 56 503 строки.
2. Дедуплицировали по `imt_id`, оставляя строку с самым длинным описанием. Строки одной карточки почти всегда отличаются только цветом (4221 карточка из 4338), а описание различается лишь у 111, поэтому так теряется меньше всего информации.
3. Удалили 113 карточек, у которых пусты и название, и описание. Осталось 48 376 карточек.
4. Очистили текст: убрали html-теги, спецсимволы, переносы строк и двойные пробелы, отделили пробелом артикулы, приклеенные к словам ("Джинсы14274-8" -> "Джинсы 14274-8").
5. Собрали единый текст `product_text`: категория, название, бренд, цвет, описание. Категория идёт первой, потому что название часто просто повторяет её или пустое.
6. Для оценки ограничили каталог пулом асессоров - 4256 карточек. Все товары из разметки в нём есть.

**2.3. Лексический поиск (baseline)**

Построили TF-IDF по текстам товаров каталога оценки. Функция `search_lexical(query, top_k)` переводит запрос в TF-IDF-вектор, считает похожесть на каждый товар и возвращает топ-K карточек с колонками `imt_id`, `imt_name`, `subj_name`, `score`.

**2.4. Семантический поиск**

Взяли мультиязычную модель эмбеддингов `paraphrase-multilingual-MiniLM-L12-v2`: она понимает русский, небольшая и считает эмбеддинги каталога на обычном процессоре примерно за минуту. Посчитали эмбеддинги всех 4256 товаров каталога оценки батчами по 64. Функция `search_semantic(query, top_k)` переводит запрос в вектор и возвращает товары с наибольшей косинусной близостью, в том же формате, что и лексический поиск. Ограничение модели: она читает только первые 128 токенов текста, поэтому конец длинных описаний в вектор не попадает.

**2.5. Оценка качества**

Реализовали Precision@5, Recall@10, HitRate@10, MRR и NDCG@10. Порог бинаризации вынесен в параметр `RELEVANCE_THRESHOLD = 2`: релевантными считаем товары с оценкой 2 и 3, товары с оценкой 1 и неразмеченные - нерелевантными. NDCG считаем по полной шкале оценок с весом `2^оценка - 1`, чтобы товар с оценкой 3 весил больше товара с оценкой 2. Метрики считаем по всем 700 запросам train на каталоге оценки.

**2.6. Результаты базового сравнения**

Метрики посчитаны на 700 запросах train, поиск идёт по каталогу оценки из 4256 карточек, порог релевантности 2.

Лексический поиск (TF-IDF): Precision@5 0.140, Recall@10 0.514, HitRate@10 0.656, MRR 0.333, NDCG@10 0.487.

Семантический поиск (эмбеддинги): Precision@5 0.063, Recall@10 0.163, HitRate@10 0.277, MRR 0.148, NDCG@10 0.149.

**Сравнение.** Лексический поиск выигрывает по всем метрикам: NDCG@10 0.487 против 0.149, HitRate@10 0.656 против 0.277. То есть лексический находит хотя бы один подходящий товар в топ-10 для двух запросов из трёх, семантический - меньше чем для трети. Из 700 запросов семантический лучше только на 85.

**Главные наблюдения.**
1. Запросы синтетические и почти всегда содержат слова из карточки, поэтому точное совпадение слов работает очень хорошо.
2. Каталог оценки решает всё: при поиске по всему каталогу NDCG@10 лексического поиска 0.064, а по пулу асессоров - 0.516. Метрика на полном каталоге отражает неполноту разметки, а не качество поиска.
3. Выбранная модель эмбеддингов слабо справляется с товарным поиском: она обучена на перефразировании общих текстов и читает лишь 128 токенов.

**Где подходы расходятся.**
- Семантический сильно лучше там, где важен смысл: "брюки школьные", "мужские полуботинки", "теплая обувь на зиму" (лексический выдаёт кроссовки "на лето" и футболку), "платье на выпускной".
- Лексический сильно лучше на запросах с брендом: "леггинсы mexx", "полуботинки gino rossi", "ref mubb" - там NDCG 1.0 против 0.0. Модель эмбеддингов не умеет точно сопоставлять редкие названия брендов.
- Типичная ошибка семантики - смешение похожих категорий: на "удобные кроссовки для бега" в топе оказались кеды и туфли.
- Типичная ошибка лексического поиска - совпадение не главного слова: на "белые футболки" первыми идут белые брюки и шорты.

**2.7. Риски и открытые вопросы по итогам недели**

1. Сравнение смещено в пользу лексического поиска: запросы содержат слова из карточек. На реальных запросах разрыв может быть меньше.
2. Результат семантического поиска сильно зависит от выбранной модели. Наша модель обучена на перефразировании общих текстов, а не на товарном поиске, поэтому вывод "семантика слабее" относится именно к ней, а не к векторному поиску вообще.
3. Порог релевантности 2 и значения K выбраны нами и не подтверждены заказчиком.
4. Метрики ограничены сверху неполнотой разметки, поэтому сравнивать их с единицей нельзя.

**Гипотезы для улучшения.**
1. Можно попробовать модель эмбеддингов, обученную для поиска (например, multilingual-e5), вместо модели для перефразирования. Требует загрузки модели.
2. Гибридный поиск: сумма скоров лексического и семантического - подходы ошибаются на разных запросах.
3. Приведение слов к начальной форме или разбиение на куски слов для TF-IDF: в запросах слова во множественном числе (футболки), а в названиях в единственном (футболка).
4. Чистка product_text от повторяющихся значений + исключение из него бренда, тк бренд можешь мешать, а много описаний повторяются для разных товаров.
